## Docker 端到端验收

1. 使用非示例密钥创建 `.env`，执行 `docker compose up --build -d`。
2. `docker compose ps` 中 MySQL、Redis、Qdrant、ai-service、backend、frontend 均应为 healthy/running；`ai-service /health/ready` 应报告模型、Embedding和 Qdrant 状态，Hash 回退时必须显示 `degraded=true`。
3. 配置 SMTP，完成邮箱验证码注册；再验证找回密码和更换邮箱，随后完成画像、可用时间、目标激活、计划生成、确认发布。
4. 检查今日任务，启动并停止学习计时，保存两版笔记。
5. 验证后续任务在前置任务未完成时不能启动；发送任务辅导消息并刷新页面，历史消息应恢复，清空后产生新会话。
6. 在知识空间创建父子分类并给文档分类；上传一份 PDF 或 Markdown，等待 READY 后提问，确认回答含引用，超出材料的问题明确拒答。
7. 对已发布计划发起优化，确认新提案能展示新增、重排或取消项，且发布前不改变现有任务。
8. 新建或选择含 READY 文档的知识空间，在计划页勾选后生成提案；确认每个任务展示文档/Chunk/页码来源，替换文档版本后旧提案发布会被判为上下文过期。
9. 创建诊断、逐题暂存、交卷两次；第二次不能重复评分或重复写幂等结果，答题结果应能显示评分版本记录。
10. 检查学习分析的每日汇总、掌握度趋势和报告指标与数据库任务、会话数据一致；总览大进度应按活动/暂停目标全部有效任务的预计分钟加权，小进度应按近 7 天计划任务数量计算，两个范围不得混用。
11. 管理员依次检查总览、用户与权限、知识目录、公共题库、AI 治理、运行记录和审计日志；验证用户搜索/分页与角色弹窗、目录依赖展示、题库筛选、三类运行记录和审计详情。普通用户访问 `/api/v1/admin/users` 应返回 403。
12. 上传损坏 PDF、伪装 DOCX、压缩炸弹样本和杀毒测试样本，分别确认被拒绝；让外部删除或主观题模型调用故意失败，确认进入可重试失败状态而不是丢失记录。
13. 对已批改答案提交申诉，分别验证撤回、拒绝和修正分数；修正后评分版本、错题状态和掌握度必须一致更新。

## 关键边界清单

- 同一用户重复注册、连续错误登录与锁定时间。
- 验证码过期、重复消费、连续输错、重发冷却，密码重置后旧密码与刷新令牌失效。
- 跨午夜时段拆分、重叠拒绝、例外日容量和 85% 上限。
- 已暂停目标不得规划，已完成任务不得再次启动，完成反转必须确认。
- 双进度口径：取消/软删除任务不能进入任何进度分母；总体进度纳入 `ACTIVE/PAUSED` 目标且不受近 7 天限制，周期完成率只统计查询区间；分母为 0 时接口 `value=null`。
- 旧画像/目标版本导致计划上下文过期，确认令牌过期或提案哈希变化时拒绝发布。
- 同幂等键同请求返回原结果；同键不同请求返回冲突。
- 用户不能读取另一用户的目标、任务、空间、文档、会话、评估或报告。
- 文件双扩展名、超限、空文件和不支持 MIME 被拒绝；对象键不使用原始文件名。
- 刷新令牌必须属于当前用户且未撤销/未过期；密码重置后旧令牌链全部失效。
- 未来任务、暂停/完成目标任务和依赖未满足任务均不能通过直接调用接口绕过页面限制。
- 任务完成/反馈事件重复投递不产生重复优化建议；Outbox 重试最终进入可观察死信状态。
- 掌握度只对存在的 Q/R/P/S 分量重新归一化，自评证据置信度不超过 0.2。
