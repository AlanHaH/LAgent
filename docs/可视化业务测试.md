# 可视化业务测试

## 打开测试控制台

项目启动后，双击根目录的 `visual-test.cmd`。控制台中可以选择场景、逐步执行、观察浏览器画面，并查看每一步的截图、网络请求、控制台信息和 DOM 快照。

也可以在 PowerShell 中运行：

```powershell
.\scripts\visual-test.ps1 -Mode ui
```

其他模式：

```powershell
# 打开真实浏览器，执行所有场景
.\scripts\visual-test.ps1 -Mode headed

# 无界面执行，适合回归测试
.\scripts\visual-test.ps1 -Mode headless

# 打开最近一次 HTML 报告
.\scripts\visual-test.ps1 -Mode report

# 只运行名称或标签匹配的场景
.\scripts\visual-test.ps1 -Mode headed -Scenario "@admin"
```

## 新增任意业务场景

复制 `frontend/e2e/scenarios/_template.json`，新文件名不要以下划线开头。保存后重新打开控制台，场景会自动出现。

定位页面元素时，优先使用：

1. `role + name`：按钮、标签页、链接等；
2. `label`：有表单标签的输入项；
3. `placeholder`：输入框占位文字；
4. `text`：稳定的页面文字；
5. `testId`：为自动化专门添加的稳定标记；
6. `css`：最后使用，页面改版后更容易失效。

支持的动作包括：

- 页面：`goto`、`screenshot`、`pause`；
- 账号：`login`，可选 `ui` 或 `api` 模式；
- 交互：`click`、`doubleClick`、`fill`、`type`、`press`、`select`、`check`、`uncheck`、`hover`、`upload`；
- 等待：`wait`、`waitFor`；
- 断言：`visible`、`hidden`、`enabled`、`disabled`、`text`、`containsText`、`value`、`count`、`url`；
- 接口：`api`，可以校验状态码，并把响应字段保存为后续步骤变量；
- 扩展：`custom`，复杂流程在 `frontend/e2e/support/custom-actions.ts` 中注册。

字符串中的 `${变量名}` 会从当前场景、项目 `.env` 或系统环境变量读取。系统自动提供 `${RUN_ID}`，用于生成不会重复的测试数据。

## 测试账号

管理员场景使用 `.env` 中现有的：

- `APP_ADMIN_USERNAME`
- `APP_ADMIN_PASSWORD`

学生场景建议增加：

- `TEST_STUDENT_LOGIN`
- `TEST_STUDENT_PASSWORD`

固定测试密码只能用于本地开发环境，不要在生产环境设置。测试跟踪文件可能包含提交的表单数据，也应按敏感文件管理。

## 测试产物

- `frontend/playwright-report/`：可视化 HTML 报告；
- `frontend/test-results/results.json`：机器可读结果；
- `frontend/test-results/artifacts/`：失败截图、视频和跟踪文件。

这些目录已加入 `.gitignore`，不会提交到版本库。
