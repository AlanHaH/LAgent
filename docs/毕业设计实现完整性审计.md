### A.2 技术架构

| 层级 | 实际项目 | 已定位的职责 |
|---|---|---|
| 前端 | `frontend/` | Vue 3、TypeScript、Vite、Pinia、Vue Router、Axios、Element Plus、ECharts；包含学习者和管理员页面 |
| Java 后端 | `backend/` | Spring Boot 3.3.5、Spring Security、MyBatis-Plus、Flyway、MySQL、Redis、JWT、事务、状态机、审计 |
| Python AI | `ai-service/` | FastAPI、模型网关、画像/目标/计划候选、任务辅导、OCR、Embedding、Qdrant、RAG、SSE |
| 微信读书 | `weread-mcp/` | 独立 MCP 服务、微信读书访问、二维码登录和 Fake 模式 |
| 权威数据 | MySQL | 17 个 Flyway 迁移文件，共定位到 87 张表 |
| 临时状态 | Redis/Memurai | 邮箱验证码、重发限制、接口限流 |
| 向量索引 | Qdrant | 支持 Local、Memory、Server 模式；向量索引为可重建派生数据 |
| 文件处理 | Java + Python | Java/Tika 提取文本，扫描 PDF 转 Python/PyMuPDF/RapidOCR |
| 后台任务 | Spring Scheduler | 文档处理、分析汇总、通知扫描、Outbox 消费、过期数据清理 |
| 部署 | Docker Compose/Nginx | 任务书要求的完整部署架构；日常本地开发使用原生进程 |
| 测试入口 | 三端测试目录 | 已发现 26 个 Java 测试源文件、14 个 AI 测试源文件、1 个前端 E2E 规格；通过情况待正式审计 |

### A.3 主要数据流

```text
Vue 前端
  ↓ JWT / REST / SSE
Spring Boot 业务后端
  ├─→ MySQL（权威业务数据）
  ├─→ Redis（验证码、限流）
  └─→ FastAPI（内部令牌、最小业务上下文）
          ├─→ OpenAI 兼容模型
          ├─→ Embedding
          ├─→ Qdrant
          └─→ WeRead MCP
  ↓
Java 二次校验、用户确认、事务持久化
```

当前仅确认组件、配置和入口存在，尚未证明每条链路真实调用、持久化或形成业务闭环。

## F. 建议第一个检查的模块及原因

建议首先检查：

> M01 身份认证、权限与用户数据隔离

原因：

- 它是所有后续模块的信任根。
- 如果当前用户解析、RBAC 或资源归属存在问题，后续画像、目标、计划、知识库、评估即使有完整代码，也不能判为完整实现。
- 管理员与学习者两类角色是任务书明确要求。
- Redis 验证码、JWT、刷新令牌、账户锁定和权限点均从这里进入。
- M01 虽不计入任务书要求的“6 个核心模块”，但必须先审计，否则无法可信验证其他模块的数据范围和越权风险。

第一阶段到此停止。收到“开始检查 M01”后，再进入 M01 的完整调用链审计；发现问题只记录和提出建议，不修改业务代码。
