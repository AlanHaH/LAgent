# 本地启动指南

## 1. 运行架构

开发环境使用「本机原生服务 + 本机代码」模式，不依赖 Docker：

| 模块 | 运行位置 | 地址或端口 |
|---|---|---|
| Vue 前端 | Windows 本机 | `http://localhost:5300`（`/api` 代理到 8080） |
| Spring Boot 后端 | Windows 本机 | `http://localhost:8080` |
| Python AI 服务 | Windows 本机 | `http://127.0.0.1:8090` |
| MySQL | 本机 Windows 服务（如 `MySQL80`） | `127.0.0.1:3306` |
| Memurai（Redis 兼容） | 本机服务 | `127.0.0.1:6379` |
| Qdrant | ai-service 内嵌（local 模式） | 无独立端口 |

Qdrant 由 Python AI 以 **local 内嵌模式**运行（`.env` 中 `AI_QDRANT_MODE=local`），不需要单独启动 6333 端口。Docker 仅用于部署/演示（见第 9 节），日常开发不用。

## 2. 首次运行前准备

### 2.1 前置依赖

- JDK 21、Maven 3.6.3 或更高版本（或用可用的 IntelliJ IDEA 内置 Maven）；
- Node.js 与 npm；
- Python 3.11～3.13；
- 本机已安装并启动 MySQL（Windows 服务）和 Memurai（监听 6379）。

### 2.2 配置 `.env`

项目根目录必须存在 `.env`，没有则从示例复制：

```powershell
Copy-Item .env.example .env
```

至少修改：两个 MySQL 密码（`MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`）、`JWT_SECRET`、`AI_INTERNAL_TOKEN`、`QDRANT_API_KEY` 与真实模型 `MODEL_API_KEY`。如需注册/找回密码，再配置 SMTP（`MAIL_HOST`、`MAIL_PORT`、`MAIL_USERNAME`、`MAIL_PASSWORD`、`MAIL_FROM`）。不要把 `.env` 提交到 Git，也不要在聊天、截图或测试报告中公开密钥。

### 2.3 首次准备 Python 环境

```powershell
cd ai-service
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,embeddings]"
cd ..
```

### 2.4 校验配置（可选）

两个脚本都支持 `-ValidateOnly`，只校验 `.env` 与依赖是否就绪、不启动服务：

```powershell
.\scripts\start-ai-local.ps1 -ValidateOnly
.\scripts\start-backend-local.ps1 -ValidateOnly
```

## 3. 日常启动

在**三个终端**分别执行。两个启动脚本都读取仅保存在本机、已被 Git 忽略的 `.env`，并把对应键映射为服务环境变量。

### 3.1 启动 Python AI 服务（端口 8090）

```powershell
.\scripts\start-ai-local.ps1
```

该窗口需要保持开启。Python AI 必须作为本机进程启动，不要通过受限沙箱或代理间接启动——沙箱可能允许进程监听端口却禁止访问外部模型 API，出现「健康检查正常，但所有 AI 调用都失败」的假正常现象。脚本会自动把 `127.0.0.1`、`localhost` 加入 `NO_PROXY`，避免本机 Clash 等代理劫持内部调用。

### 3.2 启动 Spring Boot 后端（端口 8080）

```powershell
.\scripts\start-backend-local.ps1
```

首次启动会自动执行 Flyway 数据库升级，可能等待十几秒。

### 3.3 启动 Vue 前端（端口 5300）

```powershell
cd frontend
npm install   # 首次
npm run dev
```

看到 `Local: http://localhost:5300/` 后打开该地址。

### 3.4 启动顺序

```text
本机 MySQL / Memurai
        ↓
Python AI（:8090）
        ↓
Spring Boot（:8080）
        ↓
Vue 前端（:5300）
```

后端先于 MySQL 启动会报数据库连接失败；Python AI 未启动时画像、目标推荐、计划生成、知识问答等 AI 功能不可用。

若 PowerShell 执行策略阻止 `.ps1`，使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-ai-local.ps1
```

后端脚本同理。

## 4. 服务地址

| 用途 | 地址 |
|---|---|
| 系统前端 | `http://localhost:5300` |
| 后端健康检查 | `http://127.0.0.1:8080/actuator/health` |
| Spring Boot API 状态 | `http://127.0.0.1:8080/api/v1/system/health` |
| 页面使用的真实 AI 接口状态 | `http://127.0.0.1:8080/api/v1/system/ai-health` |
| Python AI 存活检查 | `http://127.0.0.1:8090/health/live` |
| Python AI 就绪检查 | `http://127.0.0.1:8090/health/ready` |

`/health/ready` 就绪才表示模型、Embedding 和 Qdrant 均已准备好。

## 5. 停止项目

分别进入 Vue、Spring Boot 和 Python AI 所在终端按 `Ctrl + C`。

MySQL 与 Memurai 是系统服务，启动脚本不管理它们；需要时用 `net stop MySQL80`、`net stop Memurai` 停止（Memurai 服务名以本机安装为准），日常开发可保持运行。

## 6. 数据连接

### 6.1 MySQL

| 参数 | 值 |
|---|---|
| 地址 / 端口 | `127.0.0.1:3306` |
| 数据库 | `adaptive_learning`（对应 `.env` 的 `MYSQL_DATABASE`） |
| 用户名 / 密码 | `.env` 的 `MYSQL_USER` / `MYSQL_PASSWORD` |

可用 MySQL Workbench、DBeaver 等工具连接。数据库结构由 Flyway 自动创建（V1～V17），时间统一 UTC 存储。

### 6.2 Memurai / Redis

| 参数 | 值 |
|---|---|
| 地址 / 端口 | `127.0.0.1:6379` |
| 密码 | 本地开发未设置 |

Redis 主要保存验证码、重发冷却、失败次数和接口限流数据，没有相关操作时显示 0 个键属正常。Redis 不可用时业务按各模块降级策略运行，核心数据仍以 MySQL 为准。

### 6.3 Qdrant

Qdrant 内嵌在 Python AI 进程中（local 模式），没有独立管理页面。文档片段向量与检索结果都保存在 ai-service 数据目录；不要手工删除集合或数据点，否则会导致知识库文档与检索结果不一致。

## 7. 测试工具

### 7.1 可视化业务测试

双击项目根目录 `visual-test.cmd`（调用 `scripts\visual-test.ps1`），在 Playwright 可视化控制台运行公共页面、管理员学习档案以及自定义业务场景。

### 7.2 批量测试账号

双击项目根目录 `test-accounts.cmd`（调用 `scripts\test-accounts.ps1`），批量创建、查看、删除本地测试账号。测试账号统一使用 `@test.local` 邮箱，不需要邮件验证码。

## 8. 常见问题

### 8.1 前端显示 AI 接口异常

页面右上角状态灯会真实调用一次当前模型。先确认 Python AI 就绪：

```text
http://127.0.0.1:8090/health/ready
```

如果无法打开，在本机 PowerShell 窗口执行 `.\scripts\start-ai-local.ps1`。不要重复启动占用端口的既有进程。

`/health/ready` 正常但页面仍显示异常，依次检查：

1. Python AI 是否确为本机进程（非沙箱/代理间接启动）；
2. `.env` 中的 `MODEL_BASE_URL`、`MODEL_API_KEY` 和 `MODEL_NAME`；
3. API Key 是否有效、模型是否有权限、账户是否有可用额度；
4. 管理后台「运行模型与提示词」中模型配置是否已测试并启用；
5. 等待最多 60 秒让状态缓存刷新。

Python AI 的持久日志位于 `ai-service\logs\python-ai.log`，按 5 MB 轮转。日志只记录请求编号、错误码和校验失败字段，不记录 API Key 或完整请求正文。画像模型偶尔返回不合规 JSON 时会自动修复并重试 2 次；日志中的 `profile_output_repaired` 表示已自动恢复，`AI_OUTPUT_INVALID` 表示两次修复仍未通过。

### 8.2 扫描 PDF OCR

知识库先使用 Apache Tika 提取 PDF 自带的文字层，提取不足时自动调用本机 Python AI 的 PyMuPDF + RapidOCR 逐页识别，并把页码写入知识切块。OCR 默认最多处理 50 MB、100 页，单任务执行。相关配置为 `AI_OCR_ENABLED`、`AI_OCR_MAX_FILE_MB`、`AI_OCR_MAX_PAGES`、`AI_OCR_DPI`；带文字层的 PDF 不会重复识别。

### 8.3 后端无法连接 MySQL

检查本机 MySQL 服务是否已启动（如 `net start MySQL80`），并确认 `.env` 的 `MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_DATABASE` 与实例一致。

### 8.4 AI 功能全部失败

依次检查：

1. Python AI 的 `/health/live`（进程存活）；
2. Python AI 的 `/health/ready`（模型、Embedding、Qdrant 就绪）；
3. `.env` 中的模型地址、API Key 和模型名称；
4. 管理后台模型配置是否启用并已通过测试。

`live` 正常只说明进程存活；`ready` 正常才表示模型与 Qdrant 均已准备好。

### 8.5 端口被占用

默认端口：Vue `5300`、Spring Boot `8080`、Python AI `8090`、MySQL `3306`、Memurai `6379`。启动前不要同时运行另一套相同服务，也不要重复启动同一个模块。

## 9. 完全 Docker 模式（部署/演示）

```powershell
docker compose up --build -d
```

这种方式更接近生产部署（前端 Nginx :8088，MySQL/Redis/Qdrant/ai-service/backend 全部容器化），但每次改代码后通常需要重新构建镜像。日常开发优先使用本文的本地模式。
