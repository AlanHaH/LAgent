# 毕业设计答辩指南

毕业设计答辩要回答三类问题：做了什么、为什么这么做、遇到了什么困难怎么解决。评委最关心：工作量真实、技术有深度、业务逻辑自洽、能说清取舍。

## 1. 项目一句话定位

> "知序：基于 AI Agent 的自适应个人学习管理系统——用户提交学习目标，系统通过 AI 画像访谈建立学习画像，规划引擎生成个性化学习计划，学习过程有任务辅导与知识块验收，问答基于个人知识库检索增强。"

## 2. 架构讲清楚（三句话模型）

- **整体**：三个独立服务——Java 后端（业务权威）、Python AI 服务（无状态生成）、Vue 前端（交互），浏览器只访问 Java。
- **关键设计**：AI 不碰用户数据权限——Python 用内部令牌鉴权，返回的一切 Java 二次鉴权后才落库。
- **可信链路**：Agent 只生成提案，计划发布必须用户确认；任务图谱按前置依赖解锁，当天节点才可执行。

## 3. 高频问题与参考答案

**为什么用三个服务而不是单体？**
职责与演进分离：AI 链路（模型调用、向量检索、流式输出）迭代频繁且无状态可横向扩展；业务数据单一权威在 Java；前端独立部署。

**AI 生成内容如何保证可靠？**
四层：① 结构化输出 + 校验自动修复（重试 2 次）；② 引用约束——模型只能引用真实检索到的块 ID，无效引用直接拒答；③ 证据不足必须拒答，不用模型常识补全私有资料；④ 版本化——画像/计划/块测都留版本号与 promptVersion 可追溯。

**RAG 与直接问模型有什么区别？**
直接问模型只能答公开知识且会编造；RAG 基于用户上传的个人资料检索，回答带引用、可溯源。混合检索（向量 + 关键词）兼顾语义与精确匹配；权限在查询阶段下推，用户只能检索到自己的知识空间。

**计划怎么生成的？AI 排期会不会不合理？**
AI 只负责内容（目标拆解、任务设计、资料检索），排期由 Java 确定性算法完成（每天一个任务、固定时段），杜绝模型随意性；发布走幂等事务 + 用户确认，修改需重新生成版本。

**块测的依据？**
题目基于任务挂接的知识库资料由模型生成，答案随题落库，离线判分；及格线 70 分，未过可重考；目标内全部知识块通过才能完成目标。掌握度、错题本、学习报告都以此为准。

**并发与数据安全怎么保证？**
乐观锁（version）防覆盖、逻辑删除、雪花 ID；幂等键防重复提交；JWT + 角色路由守卫；审计日志全链路；密钥只存在于环境变量不进仓库。

**遇到的最大困难？**
可选素材（按你真实经历说，如）：
- 模型输出不稳定 → 结构化 schema 校验 + 自动修复循环；
- sticky 布局/长整型精度等前端细节 → 字符串处理长 ID、断点响应式；
- 流式对话与长任务 → SSE 事件约定 + 后台作业轮询恢复。

## 4. 演示流程建议（5-8 分钟）

1. 登录 → 新建目标，展示 AI 画像访谈流式输出（30 秒）
2. 目标推荐 → 计划生成 → 展示任务图谱与前置依赖（30 秒）
3. 今日任务：开始计时 → 打开知识块 → 生成资料/练习/块测（30 秒）
4. 和 Agent 讨论任务（流式 + 引用）→ 完成学习 → 块测判分（1 分钟）
5. 上传资料 → 知识空间 → 问答页带引用回答（30 秒）
6. 数据面板：掌握度、错题本、学习报告（30 秒）

## 5. 答辩注意事项

- 先讲设计取舍（为什么），再讲实现（怎么做），不要只背功能列表。
- 被问倒不要慌：诚实说"这里我采用的是 X，原因是 Y"，或"当时考虑过 Z 方案，因成本/复杂度放弃"。
- 准备好项目文档：架构图、接口约定、状态机、数据库表结构，问到细节能立刻翻到。
- 演示提前演练两遍，准备数据要真实（有历史会话、有块测记录），断网预案要有。
- 常见追问：事务边界、幂等实现、Outbox 为什么存在、RAG 权限如何隔离、前端长整型精度。
