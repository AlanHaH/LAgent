# AI Agent（智能体）入门

AI Agent 是以大语言模型（LLM）为核心、能够自主完成多步任务的程序：理解目标 → 拆解计划 → 调用工具 → 观察结果 → 迭代直到完成。与"一问一答"的聊天机器人不同，Agent 的关键是**自主性**与**工具使用**。

## 1. 大语言模型基础

- **什么是 LLM**：基于 Transformer 架构、在海量文本上预训练的神经网络，通过预测下一个 token 生成文本。代表模型：GPT、Claude、DeepSeek、Llama、Qwen。
- **Token**：模型处理文本的最小单位（中文一个字约 1~2 个 token），上下文窗口指一次能容纳的 token 总量。
- **关键能力**：指令遵循、推理（尤其是思维链 Chain-of-Thought）、少样本学习、生成结构化输出（JSON）。
- **关键局限**：知识截止时间（需检索补充）、幻觉（编造不存在的事实）、上下文窗口有限、无实时/外部能力（需工具）。
- **API 调用**：非流式返回完整回答；流式（SSE）逐 token 返回，体验更好、首字延迟低。

## 2. 提示工程（Prompt Engineering）

- **角色设定**：`你是一位耐心的学习导师…` 约束回答风格与专业度。
- **结构化输出**：要求"只返回 JSON"并给出 schema，配合输出校验（如 Pydantic）自动重试修复。
- **Few-shot 示例**：给 2~3 个输入-输出示例，比纯描述更稳。
- **思维链（CoT）**：要求"先逐步推理再作答"，显著提升数学/逻辑题准确率。
- **约束与防幻觉**：明确"只能基于给定资料回答，证据不足时拒答"，比"不要编造"更有效。
- **温度（temperature）**：越低越确定（事实问答 0~0.3），越高越有创意（头脑风暴 0.7+）。

## 3. 检索增强生成（RAG）

让模型回答"私有资料"里的问题，不重新训练模型：

1. **切块（Chunking）**：文档按语义切分为小段（几百字），保留元数据（来源、页码、标题）。
2. **向量化（Embedding）**：把每个块编码为向量（如 bge-small-zh、text-embedding-3），存入向量数据库（Qdrant、Milvus、FAISS）。
3. **检索（Retrieval）**：查询向量化后做相似度检索，常用**混合检索**：向量相似度 + 关键词（BM25）加权融合，兼顾语义与精确词匹配；还可按知识空间/权限过滤。
4. **生成（Generation）**：把检索到的证据块拼进 prompt，让模型"带引用作答"，并强制只引用真实存在的块 ID，证据不足必须拒答而不是用模型常识补全。

RAG 质量的关键：切块策略、检索相关性（重排序 rerank）、引用约束的严格执行。

## 4. Agent 核心机制

### 感知-思考-行动循环（ReAct）
反复执行：**思考（Thought）→ 行动（Action：调用工具）→ 观察（Observation）→ 再思考**，直到达成目标。这是 Agent 最基础的范式。

### 工具调用（Function Calling / Tool Use）
模型输出结构化的工具调用请求（工具名 + 参数 JSON），由程序执行真实操作（查数据库、发请求、执行代码），再把结果返回给模型。工具需要：清晰的名称、参数 schema、好的描述——描述决定模型何时调用它。

### 记忆（Memory）
- **短期记忆**：对话上下文（受窗口限制，需摘要压缩）
- **长期记忆**：外部存储（向量库 + 用户画像 + 历史偏好），按需检索注入

### 规划（Planning）
- 简单任务：一次推理直接生成步骤
- 复杂任务：任务分解（Decomposition）、反思（Reflection，执行后自我评价修正）、重规划（Re-planning）
- 关键约束：**Agent 只能生成提案，重要变更必须用户确认**（防失控）

### 多智能体（Multi-Agent）
多个角色分工协作：如规划者（Planner）、执行者（Worker）、审查者（Critic）。框架：LangGraph、AutoGen、CrewAI。适合可并行/专业化任务；小任务单 Agent 更简单可靠。

## 5. 主流框架与生态

- **LangChain**：通用组件库（模型封装、提示模板、检索、工具、Agent 循环）。
- **LangGraph**：基于图的状态机编排，显式控制节点与条件边，适合生产级复杂流程。
- **Anthropic Claude Agent SDK / OpenAI Agents SDK**：官方轻量 Agent 开发包。
- **AutoGen / CrewAI**：多智能体对话协作。
- **向量数据库**：Qdrant（本项目采用）、Milvus、pgvector。
- **Embedding 模型**：BGE 系列（中文好）、text-embedding-3、M3E。

## 6. 实际项目中的 Agent 架构要点

- **信任边界**：AI 返回的一切视为不可信输入，服务端二次鉴权后才落库；AI 不可直接修改正式数据。
- **无状态服务**：AI 服务无状态、只生成候选内容，正式数据由业务服务持久化。
- **流式体验**：SSE 推送 `started → delta* → completed/failed`，长任务用后台作业 + 轮询。
- **失败恢复**：模型输出校验失败自动修复（重试 2 次）；超时/限流映射为稳定错误码；作业失败可重试。
- **评估**：掌握度 = 块测得分（达标线如 70 分）；所有 AI 生成内容保留版本号与 promptVersion 以便追溯。
- **权限与隔离**：多用户数据必须按 user_id/知识空间隔离，检索阶段下推权限过滤。

## 7. 学习路径建议

1. 先跑通一个"提示工程 + 结构化输出"的最小应用
2. 加 RAG：文档上传 → 切块 → 向量库 → 带引用问答
3. 加工具调用：日历、搜索、计算器等真实动作
4. 组合成 Agent：目标 → 计划 → 执行 → 反馈循环
5. 生产化：错误处理、审计、评估、权限
